# TypeScript actions: contributor guide

Every automation is a **TypeScript action bundled to a committed `dist/index.js`**, run on the runner's own Node 24 (`runs: using: node24`). Nothing is installed at run time: each bundle contains its dependencies and the shared `lib/`, so an action works when another repository calls it at a pinned ref.

## Layout

```
actions/<name>/
  action.yml          runs: using: node24, main: dist/index.js (inputs declared here)
  src/index.ts        entry: reads inputs, builds the dependencies, calls the logic
  src/<logic>.ts      the logic, written against the Deps type of lib/types.ts
  src/*.test.ts       tests, importing the source directly
  dist/index.js       generated by `npm run build`, committed
  README.md
lib/                  shared typed code: validators, retry, runtime wiring, test fakes
```

## Commands

```bash
npm ci               # install from the lockfile
npm run typecheck    # tsc --noEmit (strict)
npm test             # node --test on the *.test.ts files (native type stripping, Node 24)
npm run build        # rebuild every actions/*/dist/index.js
npm run check        # all three
node .github/scripts/check-actions-layout.js
```

CI fails a pull request when a committed `dist/` differs from what `npm run build` produces (workflow `CI / Check dist`), so rebuild and commit the bundle together with the source.

## Writing code

- Erasable TypeScript only (enforced by `erasableSyntaxOnly`): no `enum`, no `namespace` with code, no parameter properties. Use string unions and plain objects.
- Relative imports use the `.ts` extension; type-only imports use `import type`.
- Only `lib/runtime.ts` and each `src/index.ts` import `@actions/core` or `@actions/github`. Logic modules take `{ graphql, core }` (`Deps`), which keeps them testable with the fakes of `lib/testing.ts`.
- Validate every input with `lib/validate.ts` before it reaches GraphQL; never build code or queries from inputs. Resolve project field and option IDs live by name; `lib/no-hardcoded-ids.test.ts` fails on ID literals.
- Every action supports `dry_run` and fails with `core.setFailed` on bad input.

## Adding an action

1. Create `actions/<name>/` with the files above, an `engine-<name>.yml` wrapper that calls it (see the existing engines), and a README.
2. `npm run check` and `node .github/scripts/check-actions-layout.js`.
3. Commit the source and the rebuilt `dist/`.

## Upgrading the toolchain

- **TypeScript is pinned to 5.9** (`~5.9.3`): version 7 crashes `@rollup/plugin-typescript`. Dependabot ignores TypeScript major updates; upgrade deliberately and check the build.
- **Node:** `.node-version` drives CI. The runner executes the bundle with its own `node24`; when GitHub retires it, change `using:` in every `action.yml` and `.node-version` together.
- Dependency updates arrive as grouped Dependabot pull requests; the `Check dist` job shows whether the bundles change.
